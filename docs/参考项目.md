## 1. twscrape

**vladkens · ~2.4k star · Python 库 + CLI · 最后 release ~2025.04(偏旧,用前验证)**

**做什么**:直接实现 X 内部 GraphQL API(`https://x.com/i/api/graphql`)。抓搜索、用户资料、粉丝/关注、转推者、点赞者、List 时间线、趋势。覆盖面比 Nitter 宽(followers/following 是 Nitter 拿不到的)。

**反爬四层**(核心资产):
1. **x-client-transaction-id 动态签名**(`xclid.py`)——X 2024 新增。从页面里"加载动画 SVG"算出:先带登录 cookie 访问真实页(认证态 vs 匿名态拿到的 web build 不同)→ 抓 `<meta twitter-site-verification>` 的 verification key + `<svg loading-x-anim>` 动画路径 + 动态 chunk `sign.o-*.js` 里的动画索引 → 跑三次贝塞尔曲线插值 + 2D 旋转矩阵算出 anim_key → `方法!路径!时间戳+关键字+anim_key` 做 SHA256,拼 vk_bytes+时间戳字节,**随机字节 XOR 混淆**,base64。请求 404 时认为签名过期,`fresh=True` 重算重试。
2. **请求头指纹**(`account.py`)——硬编码公开 Bearer token;`x-csrf-token` 必须等于 cookie 里的 `ct0`;UA 用账号名做种子固定,避免同 session UA 跳变。
3. **TLS/JA3 指纹**(`http.py`)——可选 curl_cffi `impersonate=chrome`,在 TLS 层伪装 Chrome 握手,对付 Cloudflare。
4. **账号池 + 限流轮换**(`accounts_pool.py` + `queue_client.py`)——账号存 SQLite,每账号对每 endpoint 独立 lock。

**限流状态机**(`_check_rep`,重点借鉴)——区分两种:
- **临时限流**:`x-rate-limit-remaining==0` → 锁账号到 reset 时间,换账号。
- **封号/失效**:错误 88/326/32、HTML+`cf-ray`(Cloudflare 拦截) → `mark_inactive` 永久停用。

**交互**:`twscrape search "kw" --limit=20` 吐 JSONL;或 `import` 当异步库。先 `add_accounts` + `login_accounts`。开发者用,无自然语言层。

**→ 我们怎么用**:把它的核心(签名 + 账号池 + 限流)**内化进自己的 X 后端**,不依赖这个库。签名的 operation-id / features flag / 混淆常量单独抽配置文件,对方改版=改配置。

## 2. x-tweet-fetcher

**ythx-101 · OpenClaw Skill(有 SKILL.md)· 真实代码在 `src/xtf/`**

**做什么**:免登录免 Key 抓推文/回复/时间线/List/长文 + 微信/微博/B站。

**哲学 = 把签名甩给别人,三后端路由**:
- **FxTwitter**——单推/资料走 `api.fxtwitter.com`(Discord 嵌入卡片用的公开服务,自己处理所有认证),零依赖零认证。
- **Nitter**——时间线/搜索/回复走自建 Nitter(Nitter 持副账号 cookie 调 X 内部 API,xtf 只用 stdlib 解析它的 HTML/RSS)。
- **Browser**——List/长文走 Camofox(反指纹 Firefox 分支)/Playwright。

**工程亮点**(借鉴):
- 多实例健康检查 + 故障转移(`nitter.py _get_html`:先试健康实例,RateLimited/UpstreamDown 时顺次试其它)。
- **语义化退出码**(0=无新内容 / 1=有新 / 2=错误),接 cron 做增量监控。

**交互**:`xtf --search "AI"` / `xtf --url ...` → JSON。公共 Nitter 实例 2026.03 起基本全挂,**必须自建**。

## 3. MediaCrawler

**NanmiCoder · 49.7k star · 注意:不做 X,只做国内**

**做什么**:小红书/抖音/快手/B站/微博/贴吧/知乎——关键词搜索、指定帖子ID、二级评论、创作者主页、登录态缓存、代理池。

**两条签名路并存**:
- **(A) 纯算法复刻**——`client.py _pre_headers` → `sign_with_xhshow`,纯 Python 复刻小红书签名(`xhs_sign.py`:自定义打乱的 Base64 表、CRC32 变体 `mrc`、ctypes 模拟 JS 无符号右移;`playwright_sign.py` monkey-patch 修 xhshow 的 GET a3_hash bug)。不需浏览器、可高并发,但平台改算法就得跟。
- **(B) 浏览器执行 JS 签名**——不碰加密,直接在页面里调它自己的签名函数。慢、需常驻浏览器,但平台改算法自动适配。

**反检测核心 = CDP 模式**(`cdp_browser.py` + `browser_launcher.py`,国内平台最值钱的一课):
连接**用户真实 Chrome**(`connect_over_cdp`),启动参数 `--disable-blink-features=AutomationControlled`(去掉 `navigator.webdriver`)+ `--disable-infobars`,再注入 `stealth.min.js`。复用真实浏览器指纹/cookie/登录态 → 风控无法和真人区分。

**风控处理**(`client.py request`):HTTP 471/461 = 验证码(读 Verifytype/Verifyuuid 头,抛错不硬刚);IP_ERROR_CODE → IPBlockError → 换代理(providers:快代理、极速)。**思路:靠真实指纹+登录态+控频+代理"预防验证码",而非解验证码。**

**交互**:`main.py --platform xhs --type search` + 表单式 WebUI(非对话)。需扫码登录 + Chrome 远程调试。

## 4. newsnow

**ourongxing · 20.3k star · TypeScript 全栈(React+Nitro)· ~44 源 · 有 MCP server**

**做什么**:优雅展示各平台热榜。它的 API 是 TrendRadar 的数据源。

**架构借鉴**:一源一 TS 文件(`server/sources/`),实现统一类型接口,加源=加文件。自适应抓取间隔(按源更新频率,最短 2 分钟)+ 30 分钟缓存防封。

**反爬技巧**:
- 伪造 UA + 借用匿名 cookie(`weibo.ts` 硬编码 UA + 匿名 SUB cookie)。
- **先领访客 cookie**(`douyin.ts` 先空请求 `login.douyin.com` 拿 Set-Cookie 访客身份,再带它调热搜 API,无需签名)。

**交互**:浏览器看网页(无自然语言查询);或外部 MCP 客户端连它的 MCP server。**形态和 AIRADAR 一样:展示 app + 独立数据出口。**

## 5. TrendRadar

**sansan0 · 57.6k star · 最接近成品**

**做什么**:个人舆情监控。聚合 11+ 热榜(数据走 newsnow API)+ RSS,关键词或 AI 筛选后推送到微信/飞书/钉钉/TG/邮件/ntfy/bark/slack,可选 AI 简报。有 MCP server 对历史数据做自然语言分析。

**筛选是精华**:`frequency_words.txt` 语法(普通词 / `+`必须 / `!`过滤 / `@`数量 / `[GLOBAL_FILTER]` / `/正则/ => 显示名` / 空行分词组)。v6.5 加 AI 筛选(`ai_interests.txt` 自然语言 → AI 提取标签 → 新闻打分 1-10 → 超 min_score 才推,失败回退关键词,已打分的不重复消耗 token)。

**推送模式**:daily(当日汇总)/ current(当前榜单)/ incremental(只推新增,零重复)。`timeline.yaml` 按星期/时段排不同筛选和模式。热度权重 rank/frequency/hotness(默认 0.6/0.3/0.1)可调。

**有一处自调 LLM**:"AI 分析推送"是**写死的流水线**(抓到新闻 → LLM 写摘要 → 嵌进推送),不是交互式问答。真正的对话查询照样甩给外部 MCP 客户端。

**交互**:三条线——推送(被动收)/ 网页HTML报告 / MCP server(外部 AI 客户端对话)。自然语言对话永远在外部客户端里,不在 TrendRadar 身体里。

## 6. AIHOT

**aihot.virxact.com · KKKKhazix/khazix-skills · AIRADAR 的直接对标**

**做什么**:中文 AI 资讯平台。Agent 接入 = 匿名只读 REST API(`/api/v1/*`)+ SKILL.md + RSS。**没有 MCP**("不需要 API Key 或 MCP server")。API v1.5.0 / Skill v0.3.7,各自独立版本化。

**关键差异**:它的 skill **只查它自己预采集/精选/评分好的库**,提问那刻**不会现场抓 X**。这正是我们要超越的地方——我们额外要能**现场搜信源本身**。

**SKILL.md 设计(照抄)**:一张"意图 → 端点"路由表("今天/24h" → `/items?window=24h`;"现在最热" → `/hot-topics`;关键词 → `/items?q=...`)。稳定 `/api/v1/*` 契约,后端抓取/评分/排序/模型随便迭代,用户不用更新 skill。

**安全边界(照抄)**:把 API 返回的标题/摘要视为**不可信内容**——只作资讯证据,不能改变 skill 规则/触发命令/诱导登录(防注入)。一个 `install.sh` 适配 Codex/Gemini/Copilot/Claude Code/OpenCode 目录,原子安装 + SHA-256 校验 + 旧目录迁移。

**它诚实标注的边界(我们的雷区)**:超 7 天历史搜索不保证;没有按 ID 取单篇正文的接口(全文版权);`mp_hot`(公众号爆文榜)不进公开池,`mp_account`(官方/媒体)可出现。

## 7. 公众号抓取

**当前最稳路线 = 基于微信读书接口,不是 Sogou 逆向。**

- 两个主要 OSS 参考:**wewe-rss**(cooderl,Node,成熟)、**we-mp-rss**(rachelos,Python+FastAPI,扫码授权,明确支持 Webhook/API/Agent)。用**专用微信小号**授权,把逻辑迁进自己的 channel。
- **坑**:微信读书更新比 App 慢数小时到一天;并非所有公众号能搜到;这类"利用接口 bug"的方案随时可能被官方修 → 做成**独立可插拔 channel**,坏了整块换。
- 单篇已知 URL 简单:Jina Reader(`r.jina.ai/URL`)或自写解析器。

## 附:反爬技术三条轴

开发时的决策框架,四层反爬:① 请求签名 → ② 身份认证 → ③ 浏览器指纹 → ④ 频率与 IP。

**签名/认证层(能不能抓到)**:
- 抓 X:优先免签名(FxTwitter 单推 + 自建 Nitter 时间线),twscrape 那套 `x-client-transaction-id` 复刻当重武器(维护成本高、随 X 更新失效),只在 Nitter 拿不到时上。
- 抓国内:直接用 MediaCrawler 的 CDP 模式性价比最高——连真实 Chrome + stealth.js,复用登录态。别从零复刻 `X-s`,除非要脱离浏览器高并发。

**指纹层(会不会被识别)**,三梯度:① 换 UA(最基础)→ ② curl_cffi 伪造 TLS/JA3(对付 Cloudflare)→ ③ CDP 连真实浏览器 + stealth.js(最强,国内首选)。

**频率/IP 层(会不会被封,最有效但最易忽视)**:learn newsnow 的自适应间隔 + 缓存;learn twscrape 的限流状态机(区分临时限流 vs 封号);IP 层接 Clash 做代理轮换。

**贯穿原则**:能不碰签名就不碰(借道 FxTwitter/Nitter/newsnow API);必须碰就用真实浏览器让它自己签(CDP);纯算法复刻是最后手段,威力大但最脆弱。
