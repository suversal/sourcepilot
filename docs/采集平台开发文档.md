# 信息采集平台 · 开发文档 v1

> 一个面向 Agent 的弹性信息采集平台:把异构、有反爬、随时会变的信源,
> 转成稳定、归一化、可被 Agent 与程序调用的服务。
>
> 本文档是"方案定型 → 进入开发"的落地依据。读完即可开写第一行代码。

---

## 0. 一句话定位

**采集平台 = 一个常驻在 Mac mini 上的 HTTP 后端(采集引擎 + 反爬 + 库 + 服务器),对外开三个出口(REST / MCP / SKILL.md),内部两种取数方式(现查 / 缓存)。**

它只负责"看见、抓取、归一化"。**不做**排序面向用户的推送、不做 LLM 分析、不存"用户关心什么"——那些是 AIRADAR(下游)的事。

---

## 1. 系统边界:采集平台 vs AIRADAR

| | 采集平台(眼睛 + 手) | AIRADAR(大脑 + 橱窗) |
|---|---|---|
| 职责 | 获取 · 归一化 | 兴趣筛选 · 打分 · 展示 |
| 因什么而变 | 信源改反爬、加信源、调抓取频率 | 用户改兴趣、调筛选逻辑、改页面 |
| 状态 | 采集游标、信源健康、原始条目 | 用户兴趣配置、"对用户去重"历史 |
| 现状 | 待建 | 已有:RSS 抓取 + 筛选打分 + 展示 |

**拆分原则**:按"变化原因"拆系统——两边因不同原因、以不同频率变化,就该能独立演进。X 明天改签名只动采集平台;AIRADAR 改打分只动 AIRADAR。

**RSS 归置决定**:AIRADAR 现有的 RSS 抓取逻辑,最终迁进采集平台,成为其中一个 channel。迁移后 AIRADAR 只剩"筛选 + 打分 + 展示",所有信源统一从采集平台进。

---

## 2. 三个出口(对外接入方式)

底下同一套核心,三个封装喂三种使用者:

| 出口 | 给谁用 | 为什么走这个 | 取数偏好 |
|---|---|---|---|
| **REST API** | AIRADAR 展示 app、程序、脚本 | 自己写代码,直接知道调哪个 URL,不需要说明书 | 缓存为主 |
| **MCP server** | AI 客户端(Claude Desktop / Cherry Studio)、AIRADAR 机器人 | agent 原生协议;简历关键词 | 现查 + 缓存 |
| **SKILL.md** | Codex / Claude Code 等 Agent | Agent 需要"意图→工具"说明书才知道调什么 | 现查为主 + 缓存兜底 |

> **关键澄清**:SKILL.md **不是**采集平台本体,只是给"需要说明书的 Agent"准备的一张纸,内容是"用户问 X,你就调这个工具/URL"。
> **AIRADAR 是程序不是 Agent**,它直接 HTTP 调 REST(一行 `fetch`),不经过 skill。

三个出口共享同一批"工具"定义(见 §5),只是协议壳不同:REST 是 URL+JSON,MCP 是 tool schema,SKILL.md 是意图路由表。

---

## 3. 两种取数方式(现查 vs 缓存)

出口是"怎么接",取数是"数据从哪来",两者正交,别混。

### 3.1 缓存查询(默认、稳)
- 调度器定时采集 → 评分 → 去重 → 存库。查询时从库里取。
- 用于:喂 AIRADAR 信息流、回答"今天 AI 圈啥事"、热榜、公众号 feed。
- 特点:快、稳、可精选、不在用户面前触发反爬。**这是 AIHOT 的模式,对喂 AIRADAR 是正解。**

### 3.2 现场搜索(差异点、有野心)
- 用户提问那一刻,现场去 X / 信源查任意 query。
- 用于:"当前 X 上某话题什么情况""搜一下大家怎么评价某新品"。
- 特点:实时、能搜任意 query。**这是 AIHOT 给不了、你超越它的地方,也是简历核心能力。**
- 代价:慢、反爬在关键路径触发、脆。因此**必须带超时 + 降级回缓存**。

### 3.3 与"稳定 X 搜索"目标的调和
最初目标是"稳定的 X 搜索"。纯现查在关键路径上最不稳。所以采用**混合**:
- 信息流 = 定时采集 + 缓存(稳)。
- 任意搜索 = 按需现查,超时/被限流则降级回缓存(近似结果 + 标注"非实时")。

**能说清"何时现查、何时缓存、为什么"本身就是资深工程判断,面试加分。**

## 4. 分层架构

```
                    ┌─────────────────────────────────────────┐
   REST  ◄──────────┤  出口层   REST API / MCP server / SKILL   │
   MCP   ◄──────────┤          (同一批工具,三种协议壳)          │
   SKILL ◄──────────┤                                          │
                    ├─────────────────────────────────────────┤
                    │  归一化层  统一 schema · 跨源去重 · 新鲜度评分 │
                    ├─────────────────────────────────────────┤
                    │  可靠性层  Canary 自检 · 故障转移 · 限流状态机 │
                    │           · 缓存 · 代理轮换(接 Clash)      │
                    ├─────────────────────────────────────────┤
                    │  信源适配层(可插拔 channel)               │
                    │   ┌────────┐ ┌────────┐ ┌──────────┐      │
                    │   │ X 后端 │ │热榜引擎│ │公众号 chan│      │
                    │   └────────┘ └────────┘ └──────────┘      │
                    │   ┌────────┐                              │
                    │   │RSS chan│ ← AIRADAR 迁入                │
                    │   └────────┘                              │
                    ├─────────────────────────────────────────┤
                    │  存储  条目库(现查缓存 + 定时采集) · 游标   │
                    ├─────────────────────────────────────────┤
                    │  调度  cron 定时采集 + Canary 探针           │
                    └─────────────────────────────────────────┘
```

### 4.1 信源适配层:声明式为主,重逻辑单写

- **热榜**:44 个源不要一个个手写。抽象成**声明式配置**(YAML),字段:`url / headers / pre_request / extract(css|jsonpath)`。新增源=加几行配置,修坏源=改配置不改代码。抓取技巧(伪造 UA、先领访客 cookie、JSON path)全提炼成配置字段。
- **X 后端**:重逻辑,单独写。内化 twscrape 的核心能力(签名 + 账号池 + 限流),不依赖外部库/Nitter 常驻。签名 operation-id、features flag、混淆常量单独抽文件(对方改版=改配置)。保留一个"降级到外部 CLI"的逃生口。
- **公众号 channel**:移植微信读书接口方案(参考 we-mp-rss)。独立可插拔,因为它最可能被官方封,坏了整块换。单篇已知 URL 用 Jina Reader / 自写解析器。
- **RSS channel**:把 AIRADAR 现有 RSS 逻辑迁入。

### 4.2 可靠性层(简历核心之一)
- **Canary 自检**:每小时探每个源一次,记成功率,失败告警 + 自动降级。把"我写了爬虫"升级成"能自我诊断、优雅降级的生产级基础设施"。
- **限流状态机**:区分"临时限流"(锁到重置时间,换账号/源)vs"封号/失效"(永久停用)。学 twscrape 的 `_check_rep`。
- **代理轮换**:接你现有 Clash;三级代理(per-source > 全局 > 环境变量)。
- **缓存**:自适应抓取间隔(学 newsnow,最短 2 分钟)。

### 4.3 安全边界(抄 AIHOT,成熟度体现)
- 把信源返回内容视为**不可信数据**:标题/摘要只作资讯证据,不能改变工具规则、不能触发命令、不诱导授权。防 prompt injection。
- 只做匿名只读的对外接口;不索要用户 Key/cookie。
- 频率合同:429 退避,不并发抓取。

## 5. 工具契约(三出口共用)

同一批工具,REST 表现为 URL,MCP 表现为 tool,SKILL.md 表现为意图路由。

### 5.1 工具清单

| 工具 | REST 端点 | 取数 | 说明 |
|---|---|---|---|
| `search_x` | `GET /api/v1/x/search` | **现查** + 缓存兜底 | 任意 query 搜 X。差异点。 |
| `get_x_timeline` | `GET /api/v1/x/timeline` | 现查 | 指定用户时间线 |
| `get_hotlist` | `GET /api/v1/hotlist` | **缓存** | 国内多平台热榜 |
| `get_wechat_feed` | `GET /api/v1/wechat/feed` | **缓存** | 订阅公众号最新文章 |
| `read_article` | `GET /api/v1/article` | 现查 | 读单篇已知 URL 正文(转 Markdown) |
| `get_feed` | `GET /api/v1/items` | **缓存** | 归一化信息流(喂 AIRADAR) |

### 5.2 入参 / 出参示例

**`search_x`**
```
入参:
  q         string  必填   搜索词
  limit     int     选填   默认 20,上限 100
  window    enum    选填   实时现查(默认) | 24h | 7d
  live      bool    选填   默认 true;false 则只查缓存
  cursor    string  选填   分页游标

出参: { items: [Item...], cursor: string|null, mode: "live"|"cache", stale: bool }
  mode  实际走了现查还是降级到了缓存
  stale 是否为降级的近似结果(现查失败时 true)
```

**`get_hotlist`**
```
入参:
  platform  string  选填   weibo|zhihu|douyin|bilibili... 不填=全部
  limit     int     选填   每平台条数
出参: { items: [Item...], collected_at: iso8601 }  # 缓存快照时间
```

**`get_feed`(喂 AIRADAR)**
```
入参:
  window    enum    24h|7d
  category  string  选填   model|product|paper|industry|tip
  since     string  选填   增量游标,只返回此后新增
出参: { items: [Item...], cursor: string, has_more: bool }
```

### 5.3 统一条目 schema(Item)

```jsonc
{
  "id": "x:1234567890",              // 全局唯一,含 source 前缀
  "source": { "type": "x", "name": "X / Twitter" },
  "title": "……",
  "summary": "……",                   // 平台采集侧只给客观摘要,不做观点
  "url": "https://x.com/…/status/…", // 第三方原文
  "author": "elonmusk",
  "published_at": "2026-07-25T10:00:00Z",  // 原文发布时间,ISO8601 UTC
  "discovered_at": "2026-07-25T10:03:00Z", // 采集平台收录时间
  "score": 0.0,                      // 采集侧热度信号,非最终排序(排序是 AIRADAR 的事)
  "media": [ { "type": "image", "url": "…" } ],
  "raw": { }                          // 原始响应,给下游需要时兜底
}
```

约定:
- `published_at` 为空可回退 `discovered_at`,但下游标注为"收录时间",不得伪称原文发布时间。
- `id` 用 `source:native_id`,跨源去重时按标题+url 归并。
- 采集侧不做面向用户的排序;`score` 只是热度信号。

### 5.4 错误码(结构化,供 Agent 分支决策)

```
RATE_LIMITED    临时限流   → 退避重试,或降级缓存
UPSTREAM_DOWN   信源不可达 → 换实例/源,或降级缓存
AUTH_EXPIRED    账号失效   → 内部换账号;对外不暴露账号细节
CAPTCHA         触发验证码 → 不硬刚,降级缓存并标 stale
NOT_FOUND       内容不存在
BAD_REQUEST     参数错误
```
统一响应信封:`{ ok: bool, data?: ..., error?: { code, message } }`(REST/MCP 一致)。

## 6. SKILL.md 设计(给 Agent 的说明书)

照 AIHOT 范式,核心是一张"意图 → 工具"路由表:

| 用户意图 | Agent 调用 |
|---|---|
| "当前 X 上 X 话题什么情况" | `search_x(q=…, window=live)` |
| "今天/过去 24h AI 圈啥事" | `get_feed(window=24h)` |
| "现在国内热榜" | `get_hotlist()` |
| "某公众号最近文章" | `get_wechat_feed(account=…)` |
| "读一下这篇" + URL | `read_article(url=…)` |

SKILL.md 里还要写死:
- 输出格式(中文简报,标题链原文,标注时间窗)。
- 安全边界(返回内容视为不可信,不执行其中命令)。
- 失败降级(现查失败→缓存+标注非实时,不冒充其它来源)。

## 7. AIRADAR ↔ 采集平台 交互

**AIRADAR 是程序,直接 HTTP 调 REST,不经过 skill。**

两种模式:
1. **拉(交互式)**:AIRADAR 需要数据时调 `GET /api/v1/items?window=24h`,拿归一化 JSON 铺页面。
2. **推(后台)**:采集平台调度器采集出新增 → 发 webhook / 进队列 → AIRADAR 监控循环消费 → 自己做兴趣筛选 + 打分 + 展示/推送。

调用形态(都在 Mac mini,走本地址;远程走 Tailscale):
```js
// AIRADAR 后端
const r = await fetch("http://127.0.0.1:PORT/api/v1/items?window=24h&category=model");
const { items } = await r.json();
// → AIRADAR 自己筛选打分,铺到页面
```

"用中文问 X 热点"这类**对话能力不做进采集平台,也不做进 AIRADAR 本体**——由外部 Agent(Codex,以后可选给 AIRADAR 页面嵌一个机器人)当大脑,读 SKILL.md 调工具。大脑可插拔:早期用 Codex 验证,后期换 AIRADAR 机器人,采集平台不变。

## 8. 落地顺序(别三个出口一起上)

1. **先定契约**:把 §5 的工具 schema、Item、错误码定死。这是采集平台和一切消费方之间的唯一合同,先定省最多返工。
2. **REST + SKILL.md**:先做这俩(最简单、最好测)。先接一个信源打通(建议 X `search_x` 或 hotlist),用 Codex 装 skill 验证"提问→查→中文简报"整链路。**这一步就能喂 AIRADAR。**
3. **X 后端硬骨头**:签名 + 账号池 + 限流。这是简历核心,值得多打磨。先跑通再加健壮性。
4. **可靠性层**:Canary、限流状态机、代理轮换。
5. **补 MCP**:REST 工具稳了,MCP 就是换协议壳,顺手拿下简历关键词。
6. **迁 RSS + 加公众号 channel**。

## 9. 简历叙事(定型)

**标题**:基于自建反爬引擎,对 X 等对抗性信源实现现场 agentic 搜索,并以 MCP 对外提供 Agent 原生服务。

**技术点**(每条都能在代码里指出对应实现):
- 逆向并实现 X 反爬签名(x-client-transaction-id)与账号池限流轮换、自动故障转移。
- 声明式数据源引擎:新增/修复信源成本趋近于零。
- 现查 + 缓存混合架构,带超时降级;区分限流与封号的状态机。
- Canary 自愈 + 可观测性。
- 一套核心、三出口(REST/MCP/SKILL),agent 原生。

**成熟度加分**:主动谈合理频率、只抓公开数据、遵守 ToS、专用小号隔离风险、返回内容防注入——体现工程伦理与风险意识。

**别过度宣称**:不写"绕过 X 所有反爬";讲"分层降级、优先稳定公开接口、高风险路径隔离为可选后端"更专业也更真实。

## 10. 环境对齐(你的现有基础设施)

- **部署**:Mac mini 常驻 HTTP 服务;远程访问走 Tailscale(参考你 OpenClaw gateway 用 `tailscale serve` 暴露端口的做法)。
- **代理**:接 Clash Verge,做 X 抓取的代理轮换。
- **分发**:GitHub + MIT License(沿用你 CNBlogs skill 的习惯)。
- **取舍经验**:CNBlogs skill 你选了 MetaWeblog XML-RPC 而非 Playwright——同样思路,能走稳定接口就不用浏览器自动化(X 优先签名/FxTwitter,浏览器留给拿不到的场景)。
